Rendering a GW2 **map** = a coordinated collection of placed 3D models. Done + verified 2026-07 (test map fileId 2257438/2962409 → idx 179282, a small `mapc`).

**Terrain size does NOT follow water (2026-07-16, user asked "peta daratan terlihat dikompres").** Verified in code + 3 real maps: terrain = its own `heightMapArray` (trn chunk) spanning the map's world `rect` (parm chunk); water is only a flat translucent quad at the REAL `waterSurfaceZ` (havk) drawn over cells that dip below it → water conforms to land, never the reverse. GW2 maps are SQUARE (dimX==dimY, perfect-square heightfield, square rect, 96 units/chunk): 179282=64² grid→70² heights rect±3072; 176494=256²→280² rect±12288; 181140=320²→350² rect±15360 (heightfield side = chunks×35/32). Heights read correctly (0 clamped). The "compressed" look = the terrain plane spans the WHOLE map rect (6k–30k units) while props cluster in a small central part, and `set_scene` framed the camera on the COMBINED prop+terrain bbox → camera pulled way out → props render tiny. **Fix:** `set_scene` (model_renderer.cpp) now tracks a **PROP-only** bbox (`plo/phi`) alongside prop+terrain, and frames on props when any exist (terrain-only maps fall back to the full box). Terrain still renders full-size; it just no longer drags the camera out. Verified 181140: buildings now fill the view instead of a tiny cluster on a flat green square. Also note the rendered terrain is a COARSE heightmap downsample (70²–350² over the whole map) so relief is smooth/blobby; genuinely-flat zones (181140 range only ~680u over 30720u) look like a pancake — that's real, not a bug. See [[castlemist-app]].

**Map file format:** a **`mapc`** (or `area`) PF packfile holds many chunks (`trn`=terrain, `havk`=collision, `zon2`, `env`, `prp2`=props, …). Prop placement is the **`prp2` chunk** → `PackMapPropV21` (fileTypes key resolves via the `area` container map; the `mapc` container reuses the same chunk types — Extractor's `chunkType` falls back to the global `chunks` table so it resolves for `mapc` too). `prp2.propArray[]` = `PackMapPropObjV21`, and `prp2.propInstanceArray[]` = `PackMapPropObjInstanceV21` (a base prop + a `transforms[]` list of extra `PackMapPropTransformV21{position,rotation,scale}` reusing the same model). Each prop obj: **`filename`→model fileId**, `position` float3, `rotation` float3 **Euler radians**, `scale` float, `bounds` float4.

**GW2 is Z-UP:** props sit on the XY ground plane at a near-constant Z (test map z≈−100); the dominant rotation is **rot[2] = yaw about Z**. (The model viewer's camera is Y-up; the map still renders fine via the orbit trackball, just tilt to taste.)

**Code:**
- `gw2model.hpp`: `Extractor::parseMapProps()` → `vector<MapProp{fileId,pos[3],rot[3],scale,bounds[4]}}`. CLI **`gw2dat_cli map --index N --template ...`** dumps propCount/uniqueModels/bounds/sample. Validated on idx 179282 = **14 props / 11 unique models**.
- `entry_extractor.{h,cpp}`: `PreviewKind::Map`; `ExtractedEntry.map` = `MapScene{ vector<ModelPreview> models; vector<MapInstance>{model,pos,rot,scale}; totalProps; loadedModels }`. `build_map_scene()` parses props, **dedupes fileId → loads each unique model** via `load_modl_bytes_by_fileid` + `build_model_preview` (cap **600** unique models), one instance per placement. Detection: `pf_has_chunk("prp2")` BEFORE the GEOM check (a map has prp2, no GEOM).
- `model_renderer.{h,cpp}`: `castlemist::render::SceneInstance{model,pos[3],rot[3],scale}`; **`set_scene(models, instances)`** uploads each unique model to its own `SceneModelGPU{vb,ib,mats,subs}` and stores per-instance `world = Scale·RotXYZ·Translate` (row-major); `render_scene()` orbits the scene center (reuses g_rot/g_dist so the existing drag/zoom work), draws every instance (props static → skinning off, two-pass opaque/effect). `render()` branches to `render_scene()` when `g_scene_mode`. `clear_model()` also clears the scene.
- `main.cpp`: `apply_extracted_entry` Map case → convert `MapInstance`→`SceneInstance`, `set_scene`. show_model visibility includes maps. Info panel shows prop/model/instance counts. Headless test: **`GW2_AUTOLOAD=179282`** → `shot_map.bmp` (auto-detects Map). NOTE: a map loads N models synchronously → give the headless run ~35s.

**Verified render (idx 179282):** screenshot shows 11 distinct models placed at world coords — palm tree, structures, teal platform, striped cylinders, marker rows, coral — a real coordinated scene. See [[castlemist-app]], [[gw2-skeleton]].

**TERRAIN — DONE (2026-07).** `trn` chunk = `PackMapTerrainV15`{ `dims` dword2 (tiles), `heightMapArray` array_ptr<float> (row-major heights = **Z**, GW2 Z-up), `swapDistance`, `verticesPerChunkSide`, `chunkArray`, `materials` }. World placement from the **`parm` chunk `MapParam.rect` float4** = (x0,y0,x1,y1) map world rect. Test map 179282: dims 64×64, **4900 height samples = 70×70 grid**, rect [-3072..3072]² (6144²), heights −1627..529; props fit inside the rect (same coord space). `castlemist::model::Extractor::parseTerrain()` → `MapTerrain{dimX,dimY,heights[],rect[4],hasRect,...}`. `entry_extractor.cpp build_terrain_model()` makes a **70×70 grid mesh**: vertex = (x0+i·dx, y0+j·dy, height) [world XY + Z-up height], normal from height central-diffs, one no-texture material (shader's neutral grey), sentinel heights clamped to ±4000 of the median. Added to the MapScene as a model + **identity instance** (verts already world-space). `set_scene` now expands the scene AABB by each instance's **model radius** (so the big terrain frames the whole map). CLI `map` reports terrain dims/samples/rect/heightMin-Max. Verified render: grey rolling ground with props sitting on it.

**MULTITHREADED map load (2026-07):** `build_map_scene` de-dupes prop fileIds then loads the unique models **in parallel** via a `parallel_for` worker pool (`std::thread::hardware_concurrency`, atomic work-queue) in `entry_extractor.cpp`. Thread-safe: shared read-only `Gw2Dat` for MFT lookup + `read_entry_bytes` (own file handle per call), `build_model_preview` opens its own dat, no shared mutable state, GPU upload deferred to `set_scene` (single thread). Map 179282 load+render dropped **~35s → ~10s**. Cap 600 unique models.

**DDS uncompressed preview FIXED (2026-07):** `dds.cpp parse_dds` only handled BC1–BC7 → GW2's plain **uncompressed** DDS (e.g. fileId 2590159 = 32-bit BGRA, masks B=0xFF/R=0xFF0000, no FourCC) were rejected → blank preview. Added `uncompressed_from_pixel_format` (32bpp BGRA→`B8G8R8A8_UNORM`/RGBA→`R8G8B8A8_UNORM`, 16bpp 565/1555/4444, 8bpp→R8) + `uncompressed_bpp_from_dxgi` for DX10-header uncompressed formats; pitch = width·bpp. `set_texture` (d3d_renderer) uses the DXGI format directly so the GPU does the B/R swizzle — no CPU conversion. `dxgi_short_name` labels the new formats.

**GRASS + WATER terrain shading (2026-07, procedural — NOT the game splat textures).** Added a material **`kind`** (0 normal, 1 terrain, 2 water) plumbed ModelMaterialCPU→MaterialGPU→CB `uMatKind` (replaced pad1). HLSL: VSOut now carries `up` (geometric i.nrm.z, before rotation) + `height` (world Z); PS kind==1 = **grass** (green `0.24,0.42,0.17`) blended to **rock** on steep slopes via `smoothstep(0.28,0.62, 1-up)`, lambert-lit; kind==2 = **translucent blue water** (alpha 0.78, renders in the effect/blend pass with depth-test-on/write-off so higher terrain occludes it → water pools only in depressions). `build_terrain_model` marks the terrain material kind=1 and adds a **16×16 water quad** at the **30th-percentile height** (only if there's a basin ≥4u deep), material kind=2. Verified: green rolling terrain with blue ponds in the craters, props on top. Water level = `heights[30th pct]` — tune the 0.30 for more/less flooding. render_scene sets uMatKind + routes water to the effect pass; single-model render() leaves uMatKind=0.
