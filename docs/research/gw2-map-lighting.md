**GW2 per-map environment lighting (mapc `env` chunk, PackMapEnvDataGlobalV75).** Sun/ambient live in `env`, NOT `lght` (lght here had only point/spot/volume lights, all count 0). Path: `env → dataGlobal → dataGlobal*(V75) → lighting[3]` (time-of-day presets: day/dusk/night) → each `PackMapEnvDataLightingV75{ lights: ptr_array_ptr<PackMapEnvDataLightV75>, shadowInfluence float, backlightColor byte3, backlightIntensity float }`. **`PackMapEnvDataLightV75` is byte-packed (no field alignment), 24-byte stride:** `color` byte3 @+0, `intensity` float @+3 (**unaligned**), `direction` float3 @+7 (unaligned, normalized). Verified map 182587: light0 = warm SUN color(255,233,192) intensity **1.3** dir(0.707,0,0.707); lights1-7 = dim COOL sky fills (intensity 0.1–0.3, e.g. blue (124,172,248)). So the real rig is ONE dominant warm sun + several weak coloured fills — energy-sane. `env` also carries `effect[3]` post-processing (ssaoAmount, glow, focalDepth/Range, saturation, tint) → the game renders HDR then tonemaps.

**White-model bug fixed (2026-07-17).** `model_renderer.cpp` `kHLSL` reconstruction shader (Full mode, used by single-model AND `render_scene` map props) `envLight()` summed three near-white lights (0.85+0.45+0.30) on a bright ambient → peak radiance ~2.1, so any albedo > ~0.48 clipped **flat white** after `saturate()` before gamma (the user's "putih" props). Fix, calibrated to the env rig above: one bright warm key (`kSun` 1.00,0.91,0.75, mostly Lambert), weak cool fill (`kSky`) + rim, hemisphere ambient with a non-trivial floor (`lerp(0.21..,0.34..)` so shadow-side steep cliffs keep detail, not black), ambient NOT scaled by exposure. Added `tonemapGamma()` = `1-exp(-c*1.05)` then `pow(.,1/2.2)` — exponential highlight rolloff asymptotes to 1 (no flat-white clip); replaces the hard `saturate()` in the terrain + main-model albedo paths. Note: dark rock cliffs SHOULD read near-black — the T3D reference renders them dark charcoal too.

**REAL per-map env lighting NOW WIRED into the GameShader path (2026-07-25).** `castlemist::model::Extractor::parseMapEnv(preset=-1)` (gw2model.hpp) template-navigates `env → dataGlobal(ptr) → resolveVariant("PackMapEnvDataGlobal",ver) → lighting[] (array_ptr, 3 time-of-day presets) → [preset].lights[] (ptr_array_ptr) → PackMapEnvDataLightV*{color byte3, intensity float, direction float3}`. `preset=-1` (default) AUTO-selects the BRIGHTEST preset (its dominant light's intensity is highest = daytime) — needed because the day rig is NOT always index 0 (map 181140: idx0=cool 1.2 sun, idx1=warm 1.3 sun). Dominant (max-intensity) light = sun; the rest are intensity-weighted-averaged into a fill/sky ambient colour+summed intensity. Helpers added: `rd8`, `resolveVariant(base,ver)` (nearest ≤ existing variant — template omits e.g. GlobalV77). Output `MapEnvLight{sunDir,sunColor,sunIntensity,fillColor,fillIntensity}` → copied to `MapScene.env` (`MapEnvRig` in entry_extractor.h) in `build_map_scene`. Renderer: `castlemist::render::set_environment_rig(MapEnvRig)`/`clear_environment_rig()` (model_renderer.h) store `g_env_rig`; `apply_env_uniforms()` (split out of `setup_game_uniforms`) derives shSun/shSunData/shSunColor(=color·clamp(intensity)·0.62·GW2_LIGHT)/shRed/shGreen/shBlue(DC=fill·clamp(fillI·0.30,0.12,0.55), +0.30·DC on .y sky gradient)/SunDirection from it. main.cpp calls `set_environment_rig(ms.env)` on map load and `clear_environment_rig()` on single-model load (skins fall back to the baked GW2-daylight default = MapEnvRig in-class defaults). **VERIFIED byte-exact vs the real dat**: standalone harness on mapc baseId 181140 (mftIndex 181140, `env` v75) → parseMapEnv auto-picked preset1, sun=(1.000,0.914,0.753)=(255,233,192) i=1.300 dir(0.707,0,0.707), fill=(0.683,0.834,0.958) i=1.150 — matches the gw2_parse_packfile tree. NB gw2mcp tools: extract maps by `index=` (their `base_id` is off-by-one vs mftIndex). The reconstruction `envLight` (Full mode) is still the calibrated static stand-in (not yet driven by g_env_rig).

**CAMERA-FOLLOWING HEADLIGHT + angle slider (2026-07-25).** Fixes "kamera diubah jadi gelap": the camera is fixed and the MODEL rotates (g_rot), but lights were world-fixed, so orbiting showed the dark side. Now single-model view has a headlight: key light comes from a camera-relative dir so the viewer-facing side stays lit under any orbit. `model_renderer.cpp`: `g_light_follow`(default true)+`g_light_angle`(0..1, default 0.22); `headlight_toward()` = norm(0, sin a, -cos a) with a=0.14+angle·1.70 (~8°..105°; camera looks +Z so 0°=(0,0,-1) straight at the front, larger tilts up-and-over → front darkens); `recon_light_dir()` = -toward (travel dir) when following. CB got a `lightMode` field (reused a `_cbpad` slot, no size change; HLSL `float uExposure; float uLightMode; float2 _cbpad`); `envLight()` branches: mode1 = headlight key from `-uLightDir`, else the old fixed multi-light. Single-model `render()` sets L=recon_light_dir()+lightMode; scene/map/inset stay lightMode 0 (fixed) so maps keep their env look. GameShader: `apply_env_uniforms` overrides shSun with headlight_toward when `g_light_follow && !g_scene_mode` (skins in Shader mode follow too; maps keep real env sun). API `set_light_follow/light_follow/set_light_angle/light_angle`. UI (main.cpp, single-model row): "Follow cam" push-toggle (ID_LIGHT_FOLLOW 2091) + angle trackbar (ID_LIGHT_ANGLE 2090, 0..100) next to the existing "Light" intensity slider.
