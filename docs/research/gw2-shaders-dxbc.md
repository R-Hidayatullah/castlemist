**GW2 DXBC shaders are stored in gw2.dat** (not only the .exe), inside **AMAT packfiles** (container `AMAT`, chunks `GRMT` v6 + `BGFX` v1). Confirmed + validated 2026-07-08.

**How to find a model's shader from the dat** (the tracing rule): model material's `filename` field decodes to a texture fileId → its **baseId B**; the AMAT shader package sits at **baseId B−1**. Example: model 143917 mat0 filename=fileId 14165 → texture baseId 19897 → **baseId 19896 = AMAT** (414KB) with 141 DXBC shaders (98 VSH + 43 FSH). ArenaNet groups a material's assets in consecutive baseIds: AMAT shader at B−1, then its textures.

**BGFX chunk structure** (in the dat AMAT): `AmatMaterialV*.shaders[]` → `AmatShaderV*` → `dx11Shader`/`pbrShader` = `AmatShaderBinaryV*` { `data`[byte] = bgfx VSH/FSH blob (contains DXBC), `constants`[], `samplers`[] = AmatSamplerConstant (token→samplerIndex = texture ROLE, solves the sec.6 problem), `bindings`[] }.

**bgfx shader blob format** (v11, in `AmatShaderBinary.data` and also in the 58 .exe built-in AMATGRMT blobs): magic 'VSH'/'FSH'/'CSH'+ver(u8); hashIn u32; hashOut u32 (v>=6); count u16; per-uniform {nameLen u8, name, type u8 (bit4=frag,bit5=sampler,low=UniformType 0Sampler/2Vec4/3Mat3/4Mat4), num u8, regIdx u16, regCnt u16, texInfo u16 (v>=8), texFmt u16 (v>=10)}; codeSize u32; code=DXBC; attrCnt u8; attrs u16*; constBufSize u16. Parser: `gw2mcp/tools/parse_bgfx_shaders.py` (scans for VSH/FSH, extracts DXBC to .cso). bgfx STRIPS the DXBC's RDEF reflection chunk (so D3DReflect shows cbuffers=0) but keeps ISGN + its own uniform table.

**Validated (`gw2mcp/tools/test_shader.cpp`, D3DReflect + Create*Shader):** extracted game VS+PS DXBC **load OK** in our D3D11 (`CreateVertexShader`/`CreatePixelShader` succeed). VS input signature = POSITION,NORMAL,TANGENT,BITANGENT,TEXCOORD0,TEXCOORD1 — **exactly matches our extracted vertex** (FVF tangent-frame + 2 UV). VS uniforms: ViewProjection(Mat4 reg16), World(Mat4 reg80), CameraPosition, TexTransform0A/0B/1A/1B → fill cbuffer at regIndex*16.

**Cross-checked against the real bgfx SOURCE (`SDK/BGFX/bgfx-master`, 2026-07).** The source CONFIRMS our reverse-engineered pipeline is faithful: (1) shader-blob parse is byte-exact (`renderer_d3d11.cpp` ShaderD3D11::create: magic, hashIn, hashOut@v≥6, count, per-uniform {nameSize u8,name,type u8,num u8,regIndex u16,regCount u16,texInfo u16@v≥8,texFmt u16@v≥10}, shaderSize u32, code, skip+1, numAttrs, attrs); (2) **uniform `regIndex` IS a byte offset** — `m_vsScratch`/`m_fsScratch` are `uint8_t[64<<10]` and `setShaderUniform` does `memcpy(&scratch[regIndex], val, numRegs*16)`, so cb byte-offset filling is right; (3) matrix transpose (row→column) is correct. **GW2's fork uses the SAME `BGFX_STATE_*` bit layout as vanilla** (blend nibbles srcRGB@12/dstRGB@16/srcA@20/dstA@24 within BLEND field, WRITE_Z@bit38 0x40'00000000) — confirmed by matching `include/bgfx/defines.h`. **KEY: GW2's AMAT `renderState` is a PARTIAL, blend-only word** (verified: opaque/"selected" pass = literally 0x0; transparent pass = 0x...6565000 = blend (5,6,5,6)=alpha-blend with WRITE_R/G/B/A **and** DEPTH_TEST bits all 0) — the engine ORs a base state at submit, so a FULL literal bgfx state decode would zero the write mask → invisible. So only the blend fields are trustworthy; keep full color-write + default depth. **Improved `model_renderer.cpp` blend decode to bgfx-exact (2026-07):** two-column `kBgfxBlendFactor[14][2]` (alpha channel remaps *_COLOR→*_ALPHA, which D3D11 requires), `kBgfxBlendEquation[5]` (ADD/SUB/REVSUB/MIN/MAX from bits 28-33, was hardcoded ADD), + AlphaToCoverage from bit 35 — all additive/zero-regression (only differ when the game set those bits). **What bgfx source CANNOT fix (the real remaining gap):** lighting/color — GW2 is a DEFERRED engine; offline we substitute a daylight SH rig + neutral light buffer, so lit color/shadows/emissive differ from the game. That needs the real light-buffer contents (RenderDoc capture of a live frame) or reimplementing GW2's deferred passes — NOT a bgfx-shader-mechanics issue. Per-sampler wrap/filter is also not improvable yet: `AmatSamplerBind` carries only token/textureIndex/textureSlot, no bgfx sampler flags.

**Full status + steps: `gw2mcp/SHADER_PIPELINE.md`.** Key caveat found: the selected PS is a DEFERRED shader (LightBuffer/StencilId uniforms, writes G-buffer via MRT) — single-RT draw gives G-buffer albedo, not final lit color; need a forward variant or a lighting pass. **LIGHTING SOLVED for gw2gsviewer (2026-07, "dark/black model" bug).** Two GW2 material PS families; the fix differs per family — disassemble each PS (`tools/test_shader.exe <cso>`; bgfx uniform `reg`=byte offset so cb0[N]=uniform at byte N*16):
  1. **Forward SH-lit** (world props, e.g. rock 291830 psIdx2): lighting computed IN the PS. cb0 = shRed/shGreen/shBlue (`cb0[1..3]` SH ambient per channel, float4=(Lx,Ly,Lz,**DC**); ambient=dp4(worldNormal4,shChannel)), shSun (`cb0[4]`=(sunDir,0), N·shSun=NdotL), shSunColor (`cb0[5]`), shSunData (`cb0[6]`.xyz=sun dir for spec, .w=shadow ctrl→0), AlphaRef (`cb0[7]`). Normal-mapped via TBN VS outputs v4/v5/v6; t0=diffuse t1=normal t2=alphamask **t15=shadowmap (global→bind WHITE=unshadowed)**. `color=albedo*(ambient+shSunColor*sat(N·shSun)*shadow)+spec`. All-zero=BLACK. Fix=daylight rig in main() (shSun=norm(.45,.8,.4); shSunColor=(1.25,1.16,1.0); shRed/Green/Blue=(0,~.1,0,~.3-.46)). Renders richer than gw2viewer (real normal mapping). Exact per-map match = IDA live-read the lighting globals; static leads: `PostLightShSunColor`/`PostLightShSunDir` consts, `LightBuffer.cpp` sub_140C03220=LightBuffer::Render (GW2 fully DEFERRED, G-buffer m_depth+m_normalSpec, accumulates sun+point+spot).
  2. **Light-prepass** (billboard 291982 psIdx0): samples screen-space light buffer `gSs14`/t14 (global sampler) by screen UV; `albedo*t14.rgb`. `LightBuffer` uniform `cb0[0]`.y scales it (default 0→black; set 1). Offline: t14=white 1x1.
  Generic viewer rules added to `gw2gsviewer.cpp`: PS sampler whose `textureIndex >= mat.textures.size()` = GLOBAL engine texture (light buffer/shadow map) → bind white 1x1; force output alpha=255 on PNG write (material PS writes o0.w from an often-unbound alpha-mask → alpha 0 → PNG composites transparent and LOOKED flat "white"; display artifact, NOT a render bug — cost hours of misdiagnosis).

**STIPPLE-DISCARD "empty model" bug (2026-07).** Some deferred PS (e.g. 291976 mat0, some 291977 submeshes; uniforms StencilId/StippleDensity/**fxclr**/envcol/speccp, global stipple texture at slot12/s12) start with a stipple-fade `discard`: `discard if |fxclr.x - ceil(max(|fxclr.x-fxclr.w| - stipple, 0))| - 0.5 < 0`. `fxclr` = fade/visibility; default 0 = "fully faded out" → discards EVERY pixel → model renders **empty** (geometry+bbox+matrices all fine, just nothing rasterizes — verified via a `[geo]` bbox print matching declared bounds). Fix: `put("fxclr",{1,1,1,1})` (+StippleDensity 0, StencilId 0). Result: 291977 went from blank → richly rendered (9 submeshes); 291976 draws but its single deferred env-cubemap material stays dark (samples screen-space light buffer t14 + env cubemap t13 + detail t4; offline white/zero substitutes underlight it — same deferred limitation as the billboard; needs real light buffer). NOTE: FVF bits 16-18 (0x70081/0x30081 = packed tangent-frame + F16 multi-UV) parse FINE in gw2model — the "empty" was NEVER an FVF/geometry bug (initial wrong guess); always the stipple discard.

**8-UV + ALPHA-BLEND (2026-07).** UV extended to full **8 channels** (GrFvf TEXCOORD0-7, bits 8-15; F16 modifier bits 16-23): `castlemist::model::Vertex` = `u,v` (UV0) + `uv[7][2]` (UV1-7)@56, `decodeVertices` reads all 8 (`uvOffN[8]`), viewer `sem_off` maps TEXCOORD idx→48+8*idx. A channel is present if F32-bit(0x100<<i) OR F16-bit(0x10000<<i) set (mutually exclusive). **Blend from AMAT bgfx state:** `AmatEffectV1.renderState` (qword @field-offset 8) IS the **bgfx 64-bit state word** — blend nibbles at shift 12/16/20/24 (srcRGB/dstRGB/srcA/dstA; 5/6 = SRC_ALPHA/INV_SRC_ALPHA = alpha blend), WRITE_Z = bit 0x40'00000000. `AmatSet.renderState` captured in extractAmat; viewer `bgfx_blend()` → D3D11_BLEND, two-pass draw (opaque then translucent sorted back-to-front, depth-write off). KEY: uber-material AMATs hold **one effect per render pass** (`shaderPassFlags` 0x1=opaque, 0x4001=transparent w/ blend renderState, 0x5=other); extractAmat picks by sampler-count → lands on the OPAQUE pass (renderState 0). 291977 is fully **opaque** (MODL materials sortLayer=0) so nothing blends — its "jagged/masked" look is the in-shader **alpha-test `discard`** (cutout, by design), NOT missing blend; the green tubes need **emissive/bloom** (glow term = texAlpha·cb0[4], but cb0[4]=shSunColor warm-white + no bloom post-pass). To render genuine transparency need pass-selection by sortLayer (pick the 0x4001 effect for sortLayer>0). Blend pipeline verified plumbed; untested on a real translucent model yet.

**MATERIAL-CONSTANT BINDING mechanism CRACKED (2026-07, jade-tech 291977 grey/wrong-color).** The per-material tints/glow/spec/scroll params (the long-open "we zero every non-global uniform" gap) bind via **token, not name-hash**: `AmatShaderBinaryV*.constants[]` = ordered **`AmatShaderConstantV2.token`** (token32) list; the bgfx shader's non-engine-global uniforms (short names: `speccp specpwr specstr glowstr glofade mtlness sssstr envcol envstr intscru intscrv intmodx inrmpmn/mx intflow/sc/sp intfrcl/pw inthght addnscl` etc.) pair with them **in order**; a MODL `ModelConstantDataV*` = `{name(token32), value(float4), constantFlags(dword)}` whose `name` matches an AMAT constant token writes its value to that uniform's cbuffer byteOff. Implemented: `AmatShader.constantTokens` parsed in `extractAmat`; `extract_game_material` pairs (skipping `kEngineGlobalUniforms`) -> `GameMaterial.vsConsts/psConsts` = `{byteOff,float4}`; `game_fill_cb` applies them after the shared fill. **BUT positional pairing is UNRELIABLE**: the DXBC compiler STRIPS unused constants, so `constantTokens` count > live bgfx material-uniform count (291977 PS: 29 tokens vs 20 uniforms) -> pairing drifts -> MatConstant lands in wrong uniform -> **jade rendered RED**. **SAFETY GATE added**: bind only when `count(material-uniforms)==count(constantTokens)` (aligned); else skip (291977 stays neutral, not miscolored). To bind the stripped-uniform case need the **token32 name-hash** (UNSOLVED — NOT crc32/fnv1a/fnv1/djb2/sdbm/murmur3[seeds 0..256]/jenkins on the 7-char names; tokens likely hash a LONGER internal name that bgfx truncated, e.g. mtlness->"metalness", specpwr->"specularPower"; find the hasher in IDA or read full names from DXBC RDEF if any variant keeps it), OR match by hashing live uniform names.
