> **One addition:** Token.cpp has a **second, 64-bit scheme** this note does not cover —
> `Token_Decode64`, 5 bits per character over the low 60 bits plus a 2-digit suffix from
> the top nibble. That is the `token64` in `ModelTextureDataV65`, recorded below as

**IDA-VERIFIED (2026-07-12, Gw2-64-disable-aslr.exe @0x140000000): the bgfx uniform-name hash is `bx::HashMurmur2A` with seed 0.** Proven at instruction level, not assumed.

- `sub_140C167D0` (add/update) + `sub_140C18D60` (end/finalize) = `bx::HashMurmur2A`. Constant `1540483477`=`0x5BD1E995` (MurmurHash2 `m`), `r=24`; per-4-byte block `mmix(h,k)= k*=m;k^=k>>24;k*=m;h*=m;h^=k`; finalize `mmix(h,tail);mmix(h,size);h^=h>>13;h*=m;h^=h>>15`. State {m_hash@+0, m_size@+4, m_tail@+8, m_count@+12}. Caller zeroes m_hash → **seed=0**. Matches bx source `include/bx/inline/hash.inl` begin() exactly. Prior notes wrongly tried Murmur3/one-shot — it is the **streaming "2A"** variant. Python impl: `scratchpad/murmur2a.py`.
- Same hash pair ALSO computes the DXBC content hash (shader identity, `*(a1+164)`, the "Hash %u" in create() errors). So one primitive serves both shader-identity and uniform-name hashing.
- In `sub_140B5AD60` (= bgfx `ShaderD3D11::create`, renderer_d3d11.cpp:4546/4556/4561): per uniform, if it is NOT a predefined uniform (`sub_140B6C830` returns 12) and NOT a sampler (`type & 0x20`), the engine computes `hash=Murmur2A(name,seed0)` and looks it up in a runtime uniform registry at `qword_1427A06F8+8720208` (open-addressed, bucket = `(-1615*((u16)((99338871*hash)>>16)>>3)) & 0xFFF`, linear probe, key = stored 32-bit hash) to get the uniform HANDLE.

**The 12 stock bgfx predefined uniforms** (table `off_142540980`, classifier `sub_140B6C830`): `u_viewRect, u_viewTexel, u_view, u_invView, u_proj, u_invProj, u_viewProj, u_invViewProj, u_model, u_modelView, u_modelViewProj, u_alphaRef4`. GW2's own uniforms (`World`, `ViewProjection`, `WorldView`, `CameraPosition`, `shRed/Green/Blue`, `shSun*`, `grbones`, `SubmodelId`, `TexTransform*`, `LightBuffer`, material params) are NONE of these → they are plain USER uniforms the engine sets by name via setUniform each draw. This is WHY castlemist can fill them by matching the blob uniform name. Vertex-attribute (bgfx Attrib) table = `unk_142541A70` (18 entries), classifier `sub_140B66720`.

**MATERIAL-CONSTANT BINDING SOLVED (2026-07-12) — GW2 "Token" = base-23 packed lowercase string, NOT a hash.** `sub_140E3B360` = `Token::Decode` (Arena/Services/Token/Token.cpp:30): `v = (token - 0x30000000) mod 2^32; while(v){ out += ALPHA[v % 23]; v /= 23; }` with **ALPHA = `"abcdefghiklmnopvrstuwxy"`** (23 chars, @0x1420741f8; no j/q/z, note order ...o,p,v,r,s,t,u,w,x,y). Decoder/encoder: `scratchpad/token.py`. Verified: quality token 805394902 → `"high"` (technique quality picks 'u'ltra/'h'igh/'m'edium/'l'ow, selector `sub_140BFBFD0` BgfxShader.cpp; pass build `sub_140BFC1D0`).

**The real per-material tint/glow binding**: MODL `ModelConstantDataV65 = { name(token32), value(float4), constantFlags(dword) }` where **`name` decodes via Token::Decode straight to the lowercase uniform name**. Verified on MODL 143917 (all 5 materials, every constant): `0xBEF8FD7F→gloover 0x3F45CA1E→gloptrb 0x54731015→glofade 0x303C46F3→envcp 0x304F2815→blint`; sci-fi material adds `slscale slscrol holosp holop blend holoclr(=0.53,0.19,1.0 purple) opacity` — all real bgfx material-param uniforms present in that material's AMAT shader. So castlemist constant binding = **decode token→name, match the shader's bgfx blob uniform of that name, write value at its regIndex byte offset**. No hash, no positional pairing, no safety gate needed. `constantFlags`: seen 2 (normal) and 4 (envcp — env/color?); meaning TBD. `matConstLinks[]` (ModelMatConstLinkV65) = separate (likely animated/linked consts).

**Base-23 Token is ALSO the key for ENGINE-GLOBAL shader params (2026-07-31).** `sub_140AB13E0(token32, float4)` = `GrSetGlobalParam`, writing a token-keyed registry in `BgfxDdi.cpp` at `qword_1426A6100 + 1363456` (find `sub_1409AC8F0`, insert `sub_140B01C50`). Keys decode with the same `(t − 0x30000000)` base-23 scheme, so every engine-param name is **≤7 lowercase chars** — a namespace distinct from the PascalCase shader uniform names. Verified: `0x8D43A284`→`grblcol`, `0xC04DF0F8`→`grbldir` (backlight colour/direction, set from the mapc `env` chunk by `EnvContext.cpp` `sub_140C407C0` and overridden with constants by the paper-doll widgets — see [[gw2-preview-render]]), `0x3482C79B`→`grblsm`, `0x3D55A0CC`→`grblsmb`, `0x368C09EC`→`grsmbs`. This is why hashing shader uniform names (Murmur2A of `BacklightColor` etc.) never matches these ids.

**Corrections this supersedes:** the old [[gw2-shaders-dxbc]] positional-pairing + "token hash unsolved (crc/fnv/murmur3)" note is OBSOLETE — it failed because the token is base-23 Token, not a hash. Separately, `AmatShaderConstantV*.token` (inside the AMAT, decodes to garbage under base-23, e.g. 1304194173→"ddismid") is a DIFFERENT id (likely AMAT-baked constant defaults / variant key) and is NOT needed for binding once MODL constants are decoded. BGFX-chunk `samplers[]` are `AmatSamplerStateV1{state}` (filter/wrap dword), not token→index maps.

**TEXTURE→SAMPLER binding SOLVED (2026-07-12).** Lives in `AmatShaderBinary.samplers[]` = `AmatSamplerConstantV1 { token(qword, =0/unused here), stateIndex, textureIndex, textureSlot }`. Rule: bind MODL `material.textures[textureIndex]` (dat texture → ATEX/BCn decode) to GPU sampler **stage = textureSlot** (0-6 / 13/14/15 here — matches uniform names ss0/gSs1/gSs2/ss3/gSs4/gSs5/gSs6/gSs13/gSs14/ss15; 'g' prefix = engine-global sampler), with sampler state = `BGFX.samplers[stateIndex].state` (a bgfx sampler-flags dword: bits 0-1 U-wrap, 2-3 V-wrap [1=mirror 2=clamp 3=border], bit6 MIN_point, bit8 MAG_point, bit10 MIP_point, bit16 compare; 0 = repeat+linear). `textureIndex >= material.textures.size()` (e.g. 33/34/37) = GLOBAL engine texture (light buffer/env cube/shadow) → offline stand-in. `ModelTextureDataV65 = { filename(fileId), textureFlags, token(token64, per-texture asset id, NOT a role name), blitId, uvAnimId, uvPSInputIndex(byte = which UV/TEXCOORD set the PS samples it with) }`. Verified on AMAT 19896: color PS binds slots 0-6 (material tex, repeat+linear) + 13/14/15 (globals, clamp). castlemist ALREADY implements this correctly (entry_extractor.cpp samplers loop) — texture binding was NOT the gap.

**FULL VERIFIED MODEL RENDER PIPELINE (IDA + dat, 2026-07-12):** (1) MODL `ModelPermutationData.materials[]` → ModelMaterialData{ filename(fileId→AMAT at that texture's baseId−1), materialId, materialFlags, sortOrder, textures[], constants[], texTransforms[], matConstLinks[] }. (2) AMAT = GRMT (meta) + BGFX{ shaders[], samplers[](states), techniques[] }. (4) shader blob = DXBC + uniform table{name,type,regIndex=BYTE offset,regCount}. (6) constants: MODL token→name→uniform byteOff, write float4. (7) textures: per PS sampler binding, material.textures[textureIndex]→stage textureSlot, state from BGFX.samplers[stateIndex]. (8) skinning: engine CPU-pre-skins; material VS take already-skinned POSITION/NORMAL/TANGENT/BITANGENT/TEXCOORD (no bone uniform in material VS).
