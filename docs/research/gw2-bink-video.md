**GW2 cinematics = Bink 2 in the dat.** Magic `KB2i` / `KB2j`, 1920x1080 @30 fps, 1 audio track, ~100 MB decompressed each. Samples: baseId 611275 (KB2i, 2674 f), 745724 (KB2j, 1135 f), 646122 (KB2j, 2246 f), 645137 (KB2j, 4689 f / 156 s). Bink header is the standard 44-byte layout: magic@0, size-8@4, frames@8, largestFrame@12, w@20, h@24, fpsNum@28, fpsDen@32, flags@36, tracks@40.

**Old headers + new DLL WORKS (verified end to end).** Declarations from the Bink **2.7d** SDK (`bink_2_7d.h` + `radtypes_2_7d.h`, 2017, vendored to `castlemist/third_party/bink2/`); decoding by **`gw2app/gw2_dat_dlls/bink2w64.dll` = Bink 2.7p/1.3009 (2019)**, pulled out of Gw2.dat (BINARIES 'MZx', baseId 140117 / fileId 1247272). ABI is stable across the 2.7 series — `sizeof(BINK)==1744` for both — and only the newer runtime decodes the KB2i/KB2j revisions GW2 ships. **No .lib is linked**: `src/video_player.cpp` (`gw2vid`) resolves every entry point with GetProcAddress, so a missing DLL degrades to "no video preview" instead of a load failure. Search order: `$GW2_BINK_DLL` → exe dir → `gw2_dat_dlls/` → `../gw2_dat_dlls/` (a copy already sits next to castlemist.exe). Needs **`-I third_party/bink2` and `-lversion`** added to the build recipe in [[castlemist-app]].

**Runtime facts.** `BINKFROMMEMORY` opens the already-decompressed `ExtractedEntry::decompressed` **in place** — no temp file, no second 100 MB copy; therefore the player MUST be closed before that buffer is replaced (`stop_video()` runs in apply_extracted_entry, on_entry_selected, do_open_file, and the failed-extract path). Sound: `BinkSetSoundSystem(BinkOpenXAudio2, 0)` succeeds (DirectSound/WaveOut are the fallbacks) + `BinkSetSoundTrack(1,&0)` + `BINKSNDTRACK`. Perf at 1080p: **~6.1 ms decode + ~2.3 ms BGRA convert per frame**, i.e. 90 frames play in exactly 3.00 s — huge headroom. `BinkWait()` is the clock, so `pump()` is non-blocking and a 8 ms WM_TIMER drives playback.

**SEEKING IS EXPENSIVE — and BINKGOTOQUICK is WRONG here.** ArenaNet encodes these with a **single key frame**: `BinkGetKeyFrame(n, BINKGETKEYPREVIOUS)` answers `1` for every n, `allkeys=0`. So an exact seek must replay the whole delta chain at **~3.2 ms/frame** (measured: frame 1337 of 2674 = 4.9 s; frame 2344 of 4689 = 7.0 s). `BINKGOTOQUICK` costs 5 ms but reconstructs against whatever is in the frame buffer — pixel-diffed against a full decode it was **47% of pixels wrong and showed a visibly different scene**; adding 30/120 catch-up frames only reached 15%/7.5% wrong, still obvious garbage. **Rejected — `BinkGoto(f+1, 0)` only.** The one honest saving: a FORWARD seek just decodes the in-between frames (cost ∝ distance); a backward seek restarts at the key frame. `seek_cost_estimate_ms()` drives a wait cursor + status text. `../archive-viewer/source/application/video_preview.cpp` (user's other Bink player, ImGui/OpenGL) does the same full `BinkGoto(frame, 0)`.

**MULTI-TRACK AUDIO (2026-07-26).** `open()` enumerates every sound track and opens ALL of them (`BinkSetSoundTrack(n, allIds)` — it only takes effect at BinkOpen), then selection is applied by **per-track volume** (`BinkSetVolume(bink, trackId, 0 or vol)`), so switching is instant with no reopen and no re-seek (which would cost seconds, see above). Track IDs are only readable from an opened BINK yet are what BinkSetSoundTrack needs beforehand, so `probe_tracks()` does a throwaway **video-only BinkOpen** first. API: `track_count/track/track_label/set_active_track/active_track` (-1 = mix all, the default = how the game plays it); UI = a combo shown only when `track_count()>1`. **⚠ ABI GOTCHA — the one place the 2.7d header and the 2.7p runtime disagree:** the header declares `BINKTRACK{U32 Frequency, Bits, Channels, MaxSize}` but the real 2.7p struct is `{Frequency, Channels, bufferSize, 0}` — dumped words `[0]=48000 [1]=2 [2]=154624 [3]=0` for a 48 kHz stereo GW2 cinematic, so `ht->Bits` reads 2 and `ht->Channels` reads 154624. `probe_tracks` therefore reads the words **positionally** and hardcodes bits=16 (Bink 2 always decodes to 16-bit). `BinkGetTrackType` returns `0x7000BB80` (low 16 bits = the 48000 sample rate; high half not identified). 149 binks total in the dat (120 KB2i + 23 KB2j + 6 KB2g, from the index `magic` column): 40 have 0 tracks, 105 have 1, and **4 are multi-track** — see the voice section below, which is exactly what this feature is for. Default on open = the first VOICE track (not "mix all", which would play every dubbed language at once); soloing a voice keeps id 0 audible, mirroring the game's `{0, language+1}`. UI: `hwnd_video_track` combo (ID 2100) + a **Subs** toggle (ID 2101).

**★ CINEMATIC VOICE IS *INSIDE* THE BIK, ONE TRACK PER LANGUAGE (2026-07-26, IDA-proven).** `Video.cpp` `Video::Open` (**sub_140D78170**) does exactly:
```c
BinkSetMemory(...); BinkSetSoundSystem(BinkOpenDirectSound, 0); BinkSetIO(sub_140D792D0);
U32 tracks[2] = { 0, language + 1 };
BinkSetSoundTrack(2, tracks);
BinkOpen(name, 0x02104400);  // BINKIOPROCESSOR|BINKALPHA|BINKSNDTRACK|BINKNOFRAMEBUFFERS
```
So **track id 0 = shared music/SFX bed, track id = language+1 = that language's voice**. Confirmed in the dat: of 149 binks, **4 are multi-track** — baseIds **474282** (4 tracks, 1920x816, 49.6 s), **475503** (4), **482695** (5, 98.8 s), **482774** (5, 109 s) — carrying ids `{0,1,3,4,6}` / `{1,3,4,6}` = common + English(1)/French(3)/German(4)/Chinese(6); Korean(2) and Spanish(5) simply have no dub, which is why the ids are sparse. The 1080p movies that "have no voice" are the single-track ones (id 0 only). `Video::Update` = sub_140D77720 (BinkWait→DoFrameAsyncWait→ShouldSkip loop, and **`BinkGoto(frame, 0)`** — full/exact seek, same choice as ours). `BinkSetIO`/`BinkAssetIo.cpp` = the game streams the bik out of the dat instead of loading it.
**Cheap way to find them: peek only the FIRST 64 KB of each entry** (`decompress_method0(..., 64)`) — byte 40 of the Bink header is the track count. All 149 headers read in **1.0 s**; never bulk-read the entries themselves.

**★ SUBTITLES = the CINP cinematic that drives the movie (2026-07-26, verified end to end).**
```
CINP (chunk CSCN v36) references the .bik by fileId, and holds
  ResourceData.textResource[] = TextResourceData{ qword name, dword index, dword voiceId, textEntry[] }
      TextEntryData{ wchar_ptr text, byte language }   <- language 0, the authored English source text
  sequence[] -> trackGroup[] -> track[] -> triggerKey[] = TriggerKeyData{ float time, byte flags[4],
                                                                          token64 token1, token2, float v[4] }
LINK:  triggerKey.token1 == textResource.name
```
**★ THE TRIGGER TIME IS *NOT* WHEN THE TEXT APPEARS (2026-07-26 correction — user reported cues firing early/late).** A subtitle TrackGroup holds **two** tracks that must be read together: the trigger track (type 40) whose keys **LOAD** a line, and a **flagKey track (type 0) — a 0/1 step curve that says when a line is VISIBLE**. `FlagKeyData{float time; float value}`, stride 8, read from `TrackData.flagKey` @ `8+AP`. In CINP 482659 the trigger times are 0.08/7.33/15.49/29.63/37.18/47.64/84.27 s but the 15 flagKeys give the real cues:
`5.70-7.10, 11.80-15.20, 26.80-29.40, 30.60-35.60, 37.80-41.70, 47.70-51.30, 84.30-86.59` — 7 on/off pairs for 7 lines. Rule that reproduces it exactly: **each 0→1 edge starts a cue, the next 1→0 edge ends it, and the text is the last trigger loaded at or before the start**. That yields real .srt-style start+end (`SubtitleLine{time, end_time}`) and the overlay is then a plain "is pos inside the window" test — no more 8-second hold hack. Groups with triggers but no flag track (e.g. CINP 475241) fall back to "until the next trigger, capped 6 s". **Cues are also per-SEQUENCE**: each CSCN sequence plays its own movie (482659: seq0→930214, seq1→930215, seq2→930216, seq3→930217), so `SubtitleLine.sequence` + `ExtractedEntry::cinp_video_seq` let the UI show only the selected movie's cues.
Verified: bink **482774** (fileId 930214) ← CINP **482659**, 7 lines at 0.08/7.33/15.49/29.63/37.18/47.64/84.27 s — "((Caithe: The dragon is rising.))" … "((Braham: We take the fight to Mordremoth!))" (the Heart of Thorns trailer); bink 475503 ← CINP 475241, 2 lines. Finding the CINP: invert the `{u16 lo,u16 hi}` fileref (`fileId = 0xFF00*hi+lo-0xFF00FF`) into 4 bytes and byte-search each decompressed CINP — **all 1446 packs in ~1.6 s**. Struct strides (all cross-checked against a real pack): TextResourceData 16+AP, TextEntryData ptr+1, SequenceData 24+3·ptr+8+AP (trackGroup @24+3·ptr+8), TrackGroupData 12+2·AP+1 (track @12+AP), TrackData 8+3·AP+1 (triggerKey @8+2·AP), TriggerKeyData 40. Only the **English** source text is in the CINP; localized subtitles would need `name`→textId→strs (not done).

**★ CSCN IS VERSIONED — assuming v36 silently mis-parses a third of the dat (2026-07-26, user: "most CINP say no preview").** Chunk-version histogram over all 1446 CINP packs: **v36=919, v33=450, v31=35, v35=8, v30=2, and 32 packs older than v30** (v6..v29). The layouts that actually differ:
- `ResourceData` **v30-33** = `{dword crc; array_ptr ambientLight, fileNameRef, script, textResource}`; **v34+** drops `crc` and appends `speciesResource`. **So textResource sits 4 bytes later in v30-33** — reading it with the v36 offset gave nonsense (`textResource total` came out as 3,696,942,280 across the dat; after the fix it is **2474**, of which **2265 carry inline text**).
- `TriggerKeyData` **v30-31** = `{qword name; array_ptr triggerMarker}`, a different record entirely; the 40-byte `{time, flags[4], token1, token2, v[4]}` only exists **v32+**.
- `PropertyData` **v30-31** = `{qword name; qword tokenValue; float floatValue}` (20 B, **no filename**), so pre-v32 packs expose no file refs; v32+ = `{qword value; filename pathVal; byte type}`.
- `SequenceData` / `TrackGroupData` / `TrackData` / `TextResourceData` / `TextEntryData` / `FlagKeyData` are **identical v30..v36**.
`CscnLayout cscn_layout(r, root)` derives all offsets/strides from the version (returns `ok=false` below v30) and both walkers use it. After the fix, of 1446 packs: 927 have file refs, **381 have inline dialogue**, 286 have neither, 32 are pre-v30. Verified v33 pack **352651** → 13 timed lines of the Ascalonian Catacombs intro; v36 **61863** → 33 lines of the human personal story across 3 sequences.

**Every CINP now previews.** The old rule (`kind = Cinematic` only when a movie or subtitles were found) left the rest at "(no preview available)", and the generic CSCN text fallback never fired either because `parse_cscn_summary` is gated on `pf_is(dec,"CSCN")` — CSCN is the CHUNK, the container is `CINP`. **CINP IS THE ENTRY POINT — now previewable (2026-07-26).** `PreviewKind::Cinematic`: opening a CINP pack shows the video player directly. `collect_cscn_filerefs` walks sequence→trackGroup→**prop** (`PropertyData{qword value; filename pathVal; byte type}`, stride 8+ptr+1) and collects every `pathVal` fileref; each is classified by `peek_is_bink_fileid` (reads only the first 64 KB of the entry + decompresses 64 bytes → magic test, so a 70 MB movie isn't loaded just to identify it) into `cinp_video_ids` / `cinp_other_ids`. Subtitles come straight off this same pack (no 1.6 s CINP scan — we ARE the CINP), so Subs is ON by default on this path. `load_video_by_fileid` pulls the chosen movie into `AppState::cinp_video_bytes` (must outlive gw2vid, BINKFROMMEMORY reads in place); a **Movie** combo (ID_VIDEO_CLIP 2102) switches between the movies of one cinematic via `start_cinp_video`. `stop_video_stream()` (close stream, keep subs/clip list) split out of `stop_video()`. Verified: CINP **482659** → 4 movies (930214/930215/930216/930217) + 1 asset + 7 subtitle lines, opens the 5-track 1920x816 movie; CINP **475241** → 1 movie + 3 assets + 2 lines.

**THE CINEMATIC SOUND-EVENT CHAIN, as far as it was reversed (2026-07-26).** The CSCN timeline has THREE non-empty triggerKey tracks in CINP 482659: the 7 subtitle triggers (`token2 = 94111933085730`, the same on all 7 — presumably the "show text" action) and **two single triggers with `token2 = 0`** (`token1` = 18884571869363 and 5484228915). **`token1 = 5484228915` is exactly a `HandlerDataV31.name` in the AMSP the CINP references (105242 / base 794764)** — so CSCN trigger → AMSP handler. Every one of that AMSP's 294 handlers has a 21-byte `byteCode` of the shape
`03 01 <float32> | 04 02 <token64> | 12 0E 00 00 00` (e.g. `03 01 00 00 80 40  04 02 33 B1 E2 46 01 00 00 00  12 0E 00 00 00` = float 4.0 + token 5484228915). The `04 02` operand is **usually the handler's OWN name token**, so it reads as "play sound <id>" with the handler named after its sound. **Where that sound id resolves is still unknown**: `ScriptFileDataV33` does have a `metaSound` array (→ `MetaSoundDataV31` → external ASND fileIds, which castlemist's `build_amsp_audio` already handles), but this AMSP's metaSound/scriptRef/triggerKey counts are all **0** — it is nothing but handlers. Scanning all 20,682 AMSP packs for the token (33 MB on disk, **9 s**) gives 37 hits, none of them a MetaSound definition (the biggest, base 790199, is a MusicPlaylist bank). Reversing the sound VM (`04 02`) is the open lead. Also checked and empty: `ResourceData.fileNameRef[]` (count 0) and `ambientLightResource`/`speciesResource`.

**NO VOCAL MP3 IN THE CINP — the voice IS the extra bink track (2026-07-26, checked).** The user's hypothesis that the vocals are separate MP3s inside/next to the CINP was tested and **does not hold**: CINP 482659's non-video refs are just `fileId 105242` = AMSP `ScriptFileDataV33` (294 `HandlerDataV31`, **zero filename refs, and castlemist's AMSP audio extractor returns 0 clips** — a pure event script); CINP 475241's are AMAT (material 42915), ATEU (texture 42954) and the same AMSP. Nothing audio-bearing. That leaves `Video.cpp`'s `BinkSetSoundTrack(2, {0, language+1})` as the authority: the per-language voice is a **track inside the .bik**. Single-track movies (which is most of them, and all four the user first sampled) really are music/SFX only — that is why they sound voiceless. To settle it by ear: open baseId **482774** or **474282** and switch the track combo. (An attempt to dump each track to WAV via `BinkOpenTrack`+`BinkGetTrackData` crashed — a track is only decompressed if selected by `BinkSetSoundTrack` BEFORE `BinkOpen`, and even then it faulted; abandoned as unnecessary since in-app track selection already works.)

**castlemist integration.** New `PreviewKind::Video` + `VideoMeta` (entry_extractor.h); detection is the FIRST check in `decompress_raw_entry` (unambiguous magic, and skips running a 100 MB entry past every other sniffer). Toolbar: ▶Play/❚❚Pause, ■Stop, Loop, Mute, volume + seek trackbars, `m:ss / m:ss (frame N/M)` (IDs 2094-2099, `TIMER_VIDEO=3`). A line holds until the next trigger, capped at 8 s (triggers carry a start time only).
